# Accessories Port — Forge 1.7.10 (рабочая заготовка)

Цель: перенос выбранных возможностей Accessories Fabric 1.20.1 на Minecraft Forge 1.7.10.

## Уже заложено в исходниках
- четыре отдельные косметические ячейки для шлема, нагрудника, поножей и ботинок;
- отдельное хранилище косметической брони через `IExtendedEntityProperties`;
- NBT-сохранение предметов и переключателя;
- сетевые сообщения для синхронизации предметов косметической брони между игроками, при входе и начале отслеживания игрока;
- отдельный экран с четырьмя слотами, кнопкой показа обычной брони и инвентарём игрока;
- кнопка `A` в стандартном инвентаре и клавиша `O` как альтернативное открытие;
- обработчик рендера, который временно подменяет броню только на время отрисовки игрока, не меняя фактическую броню и её характеристики;
- скопированы исходные GUI-текстуры Accessories как материалы для дальнейшей точной адаптации интерфейса.

## Важно: состояние разработки
Это **не готовый мод и не проверенный JAR**. В среде подготовки сейчас доступна Java 21, а ForgeGradle 1.2 / Forge 1.7.10 требуют старого окружения сборки (обычно JDK 8 и совместимый Gradle). Исходники требуют проверки компиляции и тестирования в клиенте и на выделенном сервере.

## Сборка
1. Установить JDK 8.
2. Открыть проект в среде с Gradle, поддерживающей ForgeGradle 1.2.
3. Выполнить `gradle setupDecompWorkspace`.
4. Выполнить `gradle build`.
5. Готовый JAR появится в `build/libs/`.

## Следующие обязательные этапы

2. Завершить безопасную синхронизацию данных и NBT-перенос при смерти/смене измерения.
3. Проверить отрисовку косметической брони на других клиентах и совместимость с бронёй из модов.
4. Восстановить расположение, иконки, вкладки и все переключатели оригинального экрана Accessories по исходным текстурам и поведению.
5. Проверить сервер без клиента и клиент без сервера.

Лицензия оригинального Accessories указана в `fabric.mod.json` как MIT. Этот проект является независимой реализацией для Forge 1.7.10, а не бинарным портом Fabric-классов.

## Исследование исходного JAR
В загруженном JAR найдены экран `AccessoriesScreen`, меню `AccessoriesMenu`, `ArmorSlot`, `ToggleButton`, переключатель косметических слотов, русская локализация и GUI-текстуры (`accessories_inventory.png`, `accessories_panel.png`, `horizontal_tabs*.png`, иконки групп/слотов). Стандартный набор слотов в `data/accessories/accessories/entity/default.json` включает hat, face, necklace, cape, back, hand, ring, wrist, belt, anklet, shoes и charm. Четыре отдельные косметические ячейки брони в этом JSON не объявлены, поэтому в Forge-версии они реализуются как отдельная функциональность, требуемая пользователем.

## Автоматическая сборка через GitHub Actions

В репозитории уже добавлен workflow `.github/workflows/build.yml`.

1. Создай пустой репозиторий на GitHub.
2. Распакуй архив проекта и загрузи **содержимое** папки `AccessoriesPort-Forge1710` в репозиторий (в корне репозитория должны находиться `build.gradle`, `src/` и `.github/`).
3. Сделай commit/push в любую ветку. Workflow также можно запустить вручную во вкладке **Actions** → **Build Forge 1.7.10 mod** → **Run workflow**.
4. Открой завершившийся запуск workflow и скачай artifact `AccessoriesPort-Forge1710-build` внизу страницы.
5. Если сборка успешна, внутри artifact будет JAR из `build/libs/`. Если сборка упала, открой шаг **Build mod** и пришли полный текст ошибки.

Workflow использует Temurin JDK 8 и Gradle 2.14.1, затем запускает `setupDecompWorkspace build`. Первый запуск может занять несколько минут из-за загрузки Forge/Minecraft зависимостей.

Важно: наличие workflow не означает, что исходники уже компилируются. Успех будет подтверждён только зелёным запуском GitHub Actions и созданным JAR-артефактом. Тестирование в клиенте и на выделенном сервере всё равно необходимо.
